# Signal

Держит `awdl0` — интерфейс AirDrop — погашенным, пока он никому не нужен, и не мешает ему
работать, когда нужен. Плюс мерилка, которая показывает max и stddev, а не только среднее.

## Зачем

AWDL (Apple Wireless Direct Link) — транспорт AirDrop, Handoff, Sidecar, AirPlay и Universal
Control. Пока интерфейс активен, радио периодически уходит с канала точки доступа. На этом Mac
это выглядело так:

| ping до шлюза, 100 пакетов | avg | max | stddev | потери |
|---|---|---|---|---|
| `awdl0` активен | 12 мс | 92–97 мс | 22 | 0% |
| `awdl0` погашен | 2,97 мс | 3,76 мс | 0,19 | 0% |

На реальном трафике через VPN разница была в разы и десятки раз: Hetzner 1,7–6,2 → 48–145 Мбит/с,
Cloudflare 45–65 → 87–137 Мбит/с. Всплески и 2–8% потерь бьют по TCP тем сильнее, чем больше RTT,
поэтому дальние маршруты складывались, а близкие держались — и полгода это читалось как
«проблема где-то в сети».

`sudo ifconfig awdl0 down` лечит, но до первого AirDrop, Handoff, пробуждения или перезагрузки.

## Что делает

**Сторож** — root-демон под launchd. Не таймер: он гасит интерфейс, который поднят дольше
grace-периода (45 с) и при этом ничего не передаёт. Идёт передача — интерфейс живёт до её конца.
Обнаружение AirDrop начинается с Bluetooth LE, поэтому macOS поднимает `awdl0` сама, когда рядом
открыли шторку — сторожу достаточно не мешать.

**Окно по требованию** — если нужно, чтобы Mac был виден заранее: `signal airdrop on 5m`.
Пароль не спрашивается: команда пишет метку времени в файл, который читает демон.

**Значок в строке меню** — состояние, счётчик перехватов за сутки, открыть окно на 5 или 15 минут.

**Мерилка** — `signal measure` печатает min/avg/max/stddev/p50/p95/p99, потери, состояние `awdl0`,
**фоновый трафик** и параметры радио, а затем пишет строку в `measurements/YYYY-MM.csv`. Если фон
велик, замер помечается недействительным: занятый аплинк поднимает RTT ровно и выглядит совсем не
так, как AWDL.

## Установка

```bash
./scripts/install.sh      # спросит пароль один раз — для демона
signal menu install       # значок в строке меню (без sudo)
```

Снять: `signal uninstall` — выгружает демона и поднимает `awdl0` обратно, логи и замеры остаются.

## Команды

```
signal status                 что с радио, сторожем и окном прямо сейчас
signal airdrop on [5m]        открыть окно; off — закрыть досрочно
signal measure [--label ...]  замер первого хопа с контекстом
signal compare                замер «до/после»: с поднятым awdl0 и без
signal history [n]            таблица последних замеров
signal log [n]                что делал сторож
signal menu install           собрать и поставить значок
```

## Что ломается, пока `awdl0` погашен

Не работает: AirDrop (приём и отправка), Handoff, Universal Control, Sidecar, AirPlay в обе
стороны, Continuity Camera, Wi-Fi-плечо «Мгновенной точки доступа».

Работает: всё чисто-Bluetooth (разблокировка Apple Watch), Continuity SMS и звонки, общий буфер
обмена — когда интерфейс успевает подняться.

При политике по умолчанию перечисленное поднимает интерфейс само и получает 45 секунд на работу;
если этого мало — `signal airdrop on 5m` или пункт в меню.

## Настройка политики

`/usr/local/etc/signal/keeper.conf`:

```bash
GRACE_SECONDS=45      # сколько живёт только что поднятый интерфейс
IDLE_SECONDS=20       # сколько можно простаивать после последней передачи
ACTIVE_BYTES=131072   # сколько байт между тиками считается передачей
TICK_SECONDS=2        # шаг цикла
```

После правки: `sudo launchctl kickstart -k system/com.dima.signal.awdl-keeper`.

## Как проверить, что всё работает

```bash
signal measure --count 100     # в покое: max < 10 мс, stddev < 1,5, потерь нет
signal compare                 # разница «поднят / погашен» в одной таблице
ifconfig awdl0 | head -1       # после окна — без флага UP
```

После перезагрузки: `signal status` должен показать сторожа работающим, `awdl0` — погашенным.

## Почему так, а не иначе

Все решения — в `knowledge/decisions.md`, вместе с отвергнутыми вариантами: почему не Ethernet
(кабель, и это было бы лучше), почему не смена канала точки доступа, почему не `NOPASSWD` в
sudoers, почему сторож смотрит на трафик, а не на таймер. История сессий — в `knowledge/journal/`.
