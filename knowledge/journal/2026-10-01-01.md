## Итог

Переключений между интерфейсами и обрывов линка сегодня не было: `en0` основной с загрузки,
первый хоп чистый по данным наблюдателя. Причина «waiting for …» в Claude Code — не на последней
миле этой машины: кандидаты — участок за роутером (провайдер/маршрут до API) или сама машина под
нагрузкой (load 25–32). Первое — предмет `veil`, не `signal`.

Замечание: наблюдатель пингует шлюз по основному маршруту, то есть при кабеле фактически меряет
`en0`, а колонки радио (RSSI, пир, повторы) пишет с `en1`. Вердикт «норма» при этом верен для
пути, которым реально идёт трафик.

Транскрипты Claude Code эпизоды «Waiting for API response» не хранят — для их времени нужен
либо `claude --debug`, либо собственная проба за роутером (решение не принято, предложено
Дмитрию; граница с `veil` — ADR-001).

**Точка входа для следующей сессии.** Если «waiting» повторится — сразу снять время и посмотреть
минуту в `link-2026-10.csv` и `log show` за ±2 мин; если первый хоп чист — передавать в `veil`.
